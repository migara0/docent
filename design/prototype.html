      Token refresh and profile switch

      Implemented Created 2026-11-03 Updated 2026-11-05 auth-servicelambda

      How the web app keeps a session alive and moves between profiles without asking the user to sign in again.

      #Overview

      A signed-in user holds one access token per browser tab. When the token is close to expiry the app calls the refresh Lambda, which asks the identity provider for a new one and returns the claims for the currently selected profile. Switching profile uses the same call with a different profile id.

      Why a profile per tab

      Two tabs can show two different profiles at the same time, so the profile id travels with every request and is never stored in a cookie.

      #How it works

      1. The app reads the exp claim and schedules a refresh 60 seconds before it.
      2. It calls POST /session/refresh with the refresh token and the selected profileId.
      3. The Lambda validates both, asks the provider for new tokens, and adds the profile's claims.
      4. The app swaps the token in memory and re-schedules the next refresh.

      #Scheduling the refresh

      The timer lives next to the token so it can never outlive it.

      session/refresh.tstypescript 
      export function scheduleRefresh(token: Token, refresh: () => Promise<Token>) {
  // refresh a minute early, but never in the past
  const wait = Math.max(token.exp * 1000 - Date.now() - 60_000, 0);
  return setTimeout(() => refresh().then((next) => scheduleRefresh(next, refresh)), wait);
}

      Clock drift

      Devices with a wrong clock refresh too late. The 60 second margin covers small drift, not minutes.

      #QA checklist

      • Refresh succeeds a minute before expiry
      • Two tabs keep two different profiles
      • Sign-out in one tab ends the other tab's session
      • Expired refresh token returns to the sign-in page

      #Questions

      What happens when the network is down?

      The app keeps using the current token until it expires, then retries with a growing delay and shows a quiet banner. Nothing is lost.

      Access token
      Short-lived proof of who you are and which profile is selected.
      Refresh token
      Long-lived secret used only to get a new access token.
